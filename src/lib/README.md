# Domain module boundaries

Implementation starts with contracts, then the mission and simulator. `contracts` is implemented; the other rows are a design map until their modules land. No empty controllers or pretend sensor outputs are supplied.

| Planned module | Boundary |
| --- | --- |
| contracts | **Implemented.** Mission clock (100 Hz ticks), world/body/render/optical frames, regions, canonical JSON + SHA-256 digests, aircraft hard limits, mission envelope, observations, belief snapshot, proposals/approvals/actuation, append-only event log, evaluator outcomes, scene metadata and strict boundary schemas. |
| simulation | **Implemented.** Seeded fixed-step twin owning hidden truth: scene validation and loading, truth-free floor-plan prior (anchors excluded), drone dynamics with swept collisions and jet recoil, actuator effects applied from the true pose (gimballed jet, glass strike), a documented simplified fire/smoke compartment model, a mobile occupant who follows perceivable cues, opens unlocked doors and never walks through fire, non-image sensors with occlusion-aware footprints, and a localization error model. Applies only harness-issued actuator batches. |
| sensors | Observable sensor payloads and quality/uncertainty estimates. |
| navigation | **Partly implemented.** `planner/`: deterministic candidate factory, offline local planner, the `/api/decisions` gateway for OpenAI Decisions (`gateway.ts`) and Gemini (`gemini-gateway.ts`, REST, no SDK) with a consensus mode that asks both, and a broker that discards stale or mismatched replies, works out consensus from the two providers' proposals itself and falls back locally without changing authority. `neural/`: worker-side FlyVis client. `reflex/`: the shared MotionController interface, a pyramidal Lucas–Kanade optical-flow baseline and the engineered readout over FlyVis T4/T5 features (both hand-tuned on synthetic fixtures so far). The trained readout is pending. |
| harness | **Implemented.** Proposal lifecycle with digest-bound approvals, rules H0–H19 revalidated against all current evidence before and during execution (among them H19, extinguishing agent: no water on a fire with an unresolved cooking-oil, fuel or live-electrical indicator from report wording, the prior's room names or crew statements; and H14's look before spraying again: a flame sighting captured before an earlier spray that reached it had ended no longer supports another spray), at-most-once metered actuation, abort/reset semantics, the motion guard every controller request passes through, supported-contingency selection (return → alternate → hold → land → explicit failure) and occupiable-space coverage for intervention regions. Only harness-issued actuator batches can reach the simulator. |
| evidence | **Implemented.** Evidence store producing the truth-free belief snapshot: conservative possible-occupant association (ambiguity kept, never silently merged), per-room coverage without any all-clear state, capture-tick ordering for late observations, rules-based report interpretation (room hint, count language, fire-class cues), a fire-class assessment per observed fire (indicators with their sources; class "unknown" unless the evidence says otherwise) and an occupancy summary that never subtracts detections from a caller's count. |
| evaluation | **Implemented (scoring).** Independent evaluator over truth: collisions, water on occupants, envelope and hard-limit breaches, exterior arrival only inside the assembly box, drone return reported separately. Paired batch runs and replay are pending. |
| persistence | **Implemented; server only.** Optional MongoDB Atlas storage of finished simulation-run bundles: strict bundle validation (simulation label, SHA-256 hashes, outcome recomputed from the evaluator result), run, event and decision documents with the replay gzipped in GridFS, aggregation and Atlas Search pipelines with a regex fallback, and the `/api/runs` handler logic (local-caller guard, rate limits, body caps). Only the `/api/runs` route handlers and scripts import it: `persistence-boundary.test.ts` fails if a client component, hook, the Web Worker or any other `src/lib` module reaches it or the `mongodb` driver. Tested offline with an in-memory repository that runs the real pipelines. |

Keep the core independent of React, rendering frame rate and cloud language-model latency. The UI issues commands and renders observations/outcomes. It does not mutate hidden world truth to make a mission succeed.

See [architecture.md](../../architecture.md) for worker ownership, Python inference, OpenAI Decisions, clocks and the Blender scene boundary, [llm-deciders.md](../../docs/llm-deciders.md) for Gemini and consensus, and [persistence.md](../../docs/persistence.md) for Atlas.

## Tests

`npm test` runs `src/**/*.test.ts` with Node's built-in runner and native TypeScript type stripping (Node ≥ 22.18), so there is no test dependency. Relative imports inside `src/lib` use explicit `.ts` extensions and `import type` for type-only imports (enforced by lint). `npm run check` runs typecheck, lint and tests.
